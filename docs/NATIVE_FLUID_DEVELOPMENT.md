# Persisted native fluid development workflow

The native mechanical input contract has one optional `potential_flow` record.
Absent records are omitted from serialization, preserving old dry input hashes.
The pure-data DTO freezes full coupled arrays, exact ordered equilibrium frames,
source identity, force basis/role, kernel grid, bounds and baseline/excitation.
It imports neither a solver nor Qt. Public ANYsolver owns mathematical admission
and exact binding/order; executable providers and unknown semantics are refused.

Both GUI and CLI submit the existing frozen native snapshot with the complete
input hash. The child process computes Newmark evidence and verifies accepted
radiation memory against final physical state before sealing success. Neutral
transport checks complete accepted timeline/body/component inventory and memory
clock/shape. Failure/cancellation keep partial diagnostics and cannot be completed
results. A solver failure with no partial record still saves failed evidence.

Saved results retain producing arrays, geometry and declaration. Project edits
cannot alter a run's inputs or make old results current. Plot/replay consume the
authoritative stored channels and rotation matrices. Loading the built-in example
shows two bodies and only prepares inputs; an explicit Jobs action runs it.

Development verification includes exact data/model serialization, legacy hashes,
deep immutability, optional backend refusal, geometry/order/bounds refusals,
actual worker/seal/save/reopen/staleness/missing sidecars, Qt model editor,
QProcess and authoritative replay/plot. The desktop viewer path has earlier
separate evidence; these new integration checks use Qt offscreen/software.
No new OpenGL/desktop qualification or real-source acceptance is claimed.

The fixture's three steps and artificial operators serve bounded development
verification. They do not substitute for full scientific/legacy W4, qualified
source semantics/equilibrium/motion envelopes, Morison/lines/contact/environmental
integration or W8-W10 gates. Evidence native-fluid-app-verified-manifest.json,
review reconciliation, exact wheel identities and task notes.
